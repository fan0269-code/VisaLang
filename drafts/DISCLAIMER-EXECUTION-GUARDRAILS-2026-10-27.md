## 0. 环境口径（开工前先看这四条）

1. 本机 `grep` 是 **toybox 0.8.13**：BRE `\|` 不交替（空 + exit 1）；ERE `\b` 被改写成**字面 `b`**（**双向错**：漏计 `not here`、假命中 `bnotb`）；`-c` 数**行**不数次数。细节与实测表见 §8。
2. 本机有 **`rg` 15.2.0**，`\b` 与交替都正常。**凡"已核查/零命中/不存在"一律用 rg 或 node**；必须用 shell grep 时写 `-E` + `[[:<:]]word[[:>:]]`，要次数写 `-oE | wc -l`。
3. 回报里凡是"零命中"，**必须附命令与输出**；且任何"零命中"脚本要内建**阳性对照**，对照不命中即非零退出——把"工具静默失效"从人的自觉变成脚本的失败模式。还要写清**模式覆盖了哪几类等价写法**：只搜 `\p{Han}` 属性转义搜不到 `[\u3400-\u9fff]` 码位区间，命令对、输出对、结论照样错。**这类错不能归到工具头上**，该防的是"我以为我搜全了"。报任何计数都要带**「版本 + 切片 + 字符集 + 口径」四元坐标**——缺任一项，同一个真数在别人手里就会变成"查无出处"（同一个 125/105/103 分属 HEAD/当前 × 全文/body 四个切片；行数也一样：`wc -l` 数的是**换行符个数、不是行数**，所以 `split('\n').length = (以换行结尾 ? wc -l + 1 : wc -l)`——只是**条件恒差 1**，末行不带换行的文件两者**相等**，185 与 186 都是真的，不写口径就没法对账）。**引用测试论证"这是既有设计"前先 `git status --short`**：`??` 未跟踪或不在 HEAD 的测试只证明"修复后的状态"，不能证明"原本的设计"（本窗口有人拿这样的测试把结论方向带反）。**且别用 mtime 当时间证据**——同批未跟踪文件实测可差三周（组件 10-27 18:12:58 vs 测试 10-06 23:27:09，两者都不在 HEAD、都只存在于工作区），复制与另存都能任意设定时间；可核的只有版本库三态（HEAD 无 / `??` / `M`）。**遍历型脚本必须打终止哨兵**（`[done] n/expected`，不等即非零退出）且一个文件只读一次——本机 fs broker 会静默截断，`readdirSync` 曾在 12 条处无声截断，输出看起来只是"少了几个"；哨兵或对照失败时**先怀疑对照写错了，再怀疑数据**。**哨兵要落在条目粒度，不与文件数混用**：`[done] edited 47/47 sentences across 15/15 files`——文件数全对而某篇少改一处，文件级哨兵一点都拦不住（实测过：3/3 文件、偏差 0、EXIT=0 三个绿灯同时亮，数据却少了 1/51，因为丢的那条是"缺席"不是"不符"）。**判定某条既有测试是否已失效时，先跑一次该测试**：通过就直接证明它还活着，比读正则可靠，且不受工具解释差异影响。**但先看它自己会不会构建**：`execFileSync('npm', ['run', 'build'])` 在 69 个测试文件里有 14 个文件、16 处（参数全是 `['run', 'build']`），跑这类"单条测试"等于替全仓构建，与上面"别在别人跑全量时构建"直接撞车——要么等一个没人跑测试的窗口，要么只读它的断言、不执行。

## 1. `readingTime` 必须等于 `ceil(words / 200)`，删词会跨档

**规则**：`tests/scheme-3-english-content-quality.test.mjs:51` 断言 `String(Math.ceil(words / 200))` **严格相等**，不是范围容差。删词后必须复算 `ceil`；跨档与 frontmatter 同批改；`tests/fan-43-germany-b1-recheck.test.js:14` 是硬编码 `readingTime: "9"`，涉及该篇时同步。

**案例（本窗口一次真实的误报，比规则本身更值得记）**：我在 18:18–18:19 之间跑 `vl-measure.mjs`，看到 8 篇 `rtOK` 为 FAIL，并把"scheme-3 是红的、8 篇待修"报给了协调人。约两分钟后复跑，**15/15 全绿，测试 `pass 1 / fail 0`**。原因不是脚本错、也不是行对齐错，而是取样撞上了并行写入——`ls -lT` 显示这些文件的 mtime 是 18:18:50，正压在我的读数窗口内：writer 已删短正文（1,374 词）但 `readingTime` 还是旧值（8），于是同一时刻多篇"看起来违约"；写入完成后是 1,362 词 / rt 7，自洽。**照那份清单去改，会把 8 处正确的 `readingTime` 改成错的。**

**三条规程（缺一不可）**：
1. 取数与下结论之间**必须复跑一次**，两次一致才报；
2. 报之前**看目标文件 mtime**——若 mtime 落在你读数前后几分钟内，说明有 writer 在场，结论作废、重取。单测的 `ok / not ok` 同理，跨窗口读数不可信；
3. **内容门禁类测试（`scheme-3-*`、`m2a-*`）在有 writer 活跃期间不能作为验收依据**。正文改写与 frontmatter（`readingTime` / `updatedDate`）不同步落盘，任何时刻都存在「文本已改、字段未改」的帧，此时红是过程态而非缺陷（**英文侧如此，中文侧正好相反，见本节末**）。**收口验证必须在所有 writer 静默之后独占跑一次，并把 `date` 与测试输出写在同一段回报里**——不要只留在心里：本窗口那场「谁的红才是真的」争议，根因就是双方各有一个时刻的绿/红，却谁也没把时刻留在产物上，事后只能靠 mtime 反推。**环境前置**：`prebuild` 的 `rm -rf dist`（约 169 文件）与 Astro 的 `deleteViteFolder`（约 50 文件）会撞 `safe-delete-bulk-guard` 默认阈值 50，报错长成 `Command failed: npm run build`，极易被误判成内容回归——跑构建/全量测试一律加前缀 `CODEBUDDY_SAFE_DELETE_BULK_THRESHOLD=100000`，详见 `drafts/EXECUTION-QUEUE-2026-10-27.md` §17。附带技巧：`assert` 一挂就中断、只报第一条，故排查要用 `vl-measure.mjs` 全表的 `rtOK` 列，不能"修一篇跑一遍"——但全表本身也是快照，同受第 1、2 条约束。**同理别在别人跑全量测试时构建**：测试会往内容目录写 4 个 `__` 前缀 fixture，并在 4 个构建窗口内存在，你的构建会把它们打进产物；`ls | grep -c '^__' = 0` 挡不住——它是**脉冲不是残留**，同一秒内可先 0 后 2。**中文侧例外**：`scheme-3-chinese-pillars.test.js:118-128` 的 `updatedDate` / `sourceReviewedAt` / `readingTime` 全是硬编码契约值，与正文写出时间无因果关系——改日期不是"修过程态"，是直接违约（`:123/:124` 立刻红），禁止"顺手同步"。中文页长度契约在 `:78-80`，口径是 `[\u3400-\u9fff]` 码位计数、窗口 1800–3000；**别换尺子**：`\p{Script_Extensions=Han}` 在这个语料上多算 5.8%，`german-a1-exam-booking-timeline` 用它是 3115（越界 115），按契约口径是 2948（余 52）——同一篇页，两种尺子两个结论。

## 2. 门禁口径 ≠ `wc -w`

**案例（2026-10-27 22:47 快照，`goethe-a1-fees-by-country.md`，187 行）**：`wc -w` = **2,041**，门禁口径 = **1,697**，差 **344** 词。同日早些时候该页为 1,916 / 1,793——**两组数都对**，因为期间又删了 3 处句子（L82/L96 措辞收敛、L119 句式改写、四行标签加空行）。**门禁口径永远跟着磁盘当前状态走，不要把历史快照当基准。**

**关键**：两口径的差值**不是常数**。费用页差 344 是因为它表格分隔符与粗体标记密集；散文为主的页面差值会小得多。**只能各自现算，不能用一个差值换算另一篇。**

**度量脚本本身必须自证**，三条都是本窗口的静默缺陷：
1. **否定计数要大小写不敏感**（`/i`）。句首 `Never promote an item…` 会被漏计，`german-a1-documents-checklist` 曾因此报 17、实为 18。
2. **词类字符集必须含弯引号 `’`（U+2019）**，权威写法见 `scheme-3:33` 的 `['’-]`。漏掉会把 `centre’s` 劈成两词。
3. **词数虚增会掩盖真实 FAIL**（这是假绿，比假红更危险）。判据：`d = 200·ceil(w/200) − w`，`a` = 弯撇号词数，**`a > d` 时跨档翻转**。实测 `goethe-a1-test-centers` 真值 1,582（ceil 8），虚增后 1,602（ceil 9），脚本一度显示 `rt 9 / ceil 9 ok`，而按真值 rt=9 实为违约。

**规程**：跑数前先用已知输入验探针，两条够用——`the centre’s don’t` → 3 词 / 1 否定（守第 1、2 条）；`Never assume. Not yet. It cannot.` → 3 否定（专守大小写）。

正确口径（抄自 `tests/scheme-3-english-content-quality.test.mjs:29-33`）：

```js
const bodyOf = (s) => s.replace(/^---\s*[\s\S]*?\n---\s*/, '');
const wordsOf = (b) => b
  .replace(/https?:\/\/[^\s)]+/g, ' ')
  .replace(/<[^>]+>/g, ' ')
  .match(/\b[\p{L}\p{N}][\p{L}\p{N}'’-]*\b/gu) ?? [];
```

## 3. 删句前，先确认它是不是某条正则的唯一支撑

**案例**：`goethe-a1-fees-by-country.md` 的 `**Boundary:** This fallback is not a Germany or Beijing fee…`（L120）是 `tests/m2a-local-fees-centres.test.mjs:121` 的**唯一**支撑（`/Boundary:\*{0,2}[^\n]*not a Germany or Beijing fee/i`）。

**本节最该记住的不是这个结论，而是我差点写错的理由**：我一度写成"它同时是 `:127`（`/does not prove.*seat|does not.*guarantee.*seat/i`）的唯一支撑"。把正则逐行展开后实测，`:127` 有 **两行**支撑——L106 与 L120。L106 之所以也满足，是因为该正则**没有 `s` 标志**，只在一行内匹配，而 `does not prove … seat status` 同行远距离共现就够了。**删 L120 不会让 `:127` 红，只会让 `:121` 红。**

**判据（可机械执行，别靠读句子猜）**：把该断言的正则展开到 md 每一行，统计「有几行能单独满足它」：**== 1 → 唯一支撑，删那行必红；≥ 2 → 多重支撑，删到只剩 0 行才红**。本页实测：`:121` → `[120]` 唯一；`:127` → `[106,120]` 两处。**清单里不允许出现"抓不到/不可静态分析"**——那不是一个结论，是一张静默豁免条：写了它，那一条就再没人核。正解是换一种能核验的形式，比如把 `new RegExp(authority,'i')` 这条循环展开成 4 条字面串、各自带 `i` 逐行数（本窗口实测某页四条串的支撑密度是 2 / 12 / 6 / 1，最脆的那条正是"抓不到"的那条）。**每一行给出行号或展开后的字面量，不许写"—"。**

处方 §4.4 的 C5 要求删 L120。照删 `:121` 必红，且删掉的是一句事实披露（P5 只说"会变、去核实"，没表达"兜底≠德国或北京价"，不等价）。本页最终跳过 C5。

**规程**：整句前 8–10 词 grep `tests/` 一次；再用**关键名词短语**各 grep 一次（上例只有搜 `not a Germany or Beijing fee` 才命中）。**方向提醒**：`assert.match` 是"必须有"，删了会红；`assert.doesNotMatch` 是"不许有"，删了反而更容易绿，别把绿当安全信号。

## 4. 单测可以跑，但"绿"不等于契约完好

`npm test` / `npm run build` 仍然禁止（并行 worker 会撞车）。**允许**跑单个只读 `src/` 的测试：`node tests/<某文件>.test.js`，鼓励在改完后跑一次相关的那一个。

**但要注意三种假绿**：①断言没绑到那句话，它匹配的是别处同型文本；②只匹配前 N 个字符，你改的尾部它看不见；③`assert.doesNotMatch` 天然偏绿，删内容只会让它更容易通过。

**判断方法**：把该断言的正则展开到 md 逐行，数「有几行能单独满足它」（§3 的机械判据）。本窗口正是这样发现 `:121` 只有 L120 一行撑着、而 `:127` 有两行——**所以"删一句会红两条"这种直觉断言，必须先展开再说话**。

**`doesNotMatch` 的 0 要读对**：对这类断言，展开后数出 **0 行支撑正是通过状态**，不是缺陷，更不要去"补支撑"——补支撑等于往正文塞回被禁词。只有 `assert.match` 的 0 才是红。

## 5. 删句必然产生代词/指代悬空，必须同批修

**案例一（先行词被删）**：删掉 `This is a Beijing fee route, not a China-wide route.` 后，下一句以 `It does not prove…` 开头，`It` 失去先行词 → 改为 `This Beijing route does not prove…`（本页 L106）。

**案例二（指代对象在降级态消失）**：原句 `The two Beijing rows in the verified local fee records above are the amounts…` 断言"上面那两行"存在。registry 过期后 `getLocalFeeSchedule` fail-closed，组件只渲染 `Status: needs authority confirmation`，**"above" 里没有那两行** → 改为条件式 `the amounts the verified fee records above currently show for Beijing`（本页 L96）。此类句在正常态读得通、测试也抓不到，只在到期后撒谎。

**案例三（场景错配，正常态就指代不清）**：`## Every other location` 讲的是"两个 scope 之外的地点"，而句中出现 `Use either row only as…`，读者会问"哪两行" → 改为 scope-based 的 `Use a published amount only for the scope it was printed for; …`（本页 L122）。

**规程**：删完任何句子，回读**前后各两句**，凡出现 `it / its / they / them / both / either / the above / these / those / the former` 都点名先行词；先行词已删就补实，指代物在某种状态下会消失就改条件式或去掉指代。

## 6. 合并改写：保住"正面信息"，并躲开四类"改为"撞车

**案例**：处方 C4 原文 `A complete pack makes conflicts visible; it does not guarantee acceptance…` 整句删会连带删掉前半句的事实——"证据包能让冲突可见"正是这页要读者做的事，正解是只删分号后的免责半句（本页 L159）。处方 R4 原文 `Enter only a sourced fee or a personal estimate with its owner and date; do not copy the example prices into an unrelated location.` 成稿只覆盖后半句，前半句是工作表填写规则（表头有 `Source or assumption` 列），正解是拆成两句（本页 L132）。

**「改为」四类撞车**（按"直接落地破坏什么"分，四类都不可逆）：① **重复**——改为与相邻句已有表述重合 ≥1 个分句（checklist R2：处方 L363 vs 现 L74）；② **不成句**——改为小写开头、无终止标点、非完整主谓（vs-telc R2：处方 L575 vs 现 L98）；③ **丢内链**——原文含 `](/…)` 而改为不含（study-plan R4：处方 L748 vs 现 L187，原文有 `[exam comparison](/guides/goethe-b1-vs-telc-b1/)`）；④ **半句覆盖**——原文 ≥2 分句而改为只覆盖其中一半（fees R3：处方 L617 vs 现 L87）。**处置一律：只删不插，或把缺失部分补回成稿。**

**删前三分支**：① 句内含内链 → 只删分句、保住链接（fees L40）；② 在表格行内 → 只删该格文字、行结构不动（checklist L70）。**但"行结构"这层损失没有任何测试兜底，且行内各格并不等价**：承载唯一支撑的格动即红，其余格改写红 0，而 `|` 弄丢、列数不一致、格内容错位**全绿**（护理页实测：删格文字红 1、整行删红 1、只改后两格红 0）；同页本就可以有两张列数不同的表（L44 三列 / L81 六列，`telc-work-nursing.test.js:29` 那条六列表头断言钉的是后者），按"同页列数该一致"去统一，必把前者改坏且不报错；③ 否定只在分号后半 → 先查前半是否已被页面级组件覆盖，覆盖则整句删（checklist C1），未覆盖则只删后半（study-plan L61 保留 `Put the source URL and date beside the note.`）。

**规程**：遇到「事实 + 免责」用分号 / `but` / `and` / 冒号连接的句子，按**分句**处置，不整句删。删前先问"删掉后读者少知道了什么具体做法"，答不上来才允许整句删。

## 7. 处方行号不可信，密度预估也不可信

**行号案例**：本窗口所有处方行号都因先前改动整体偏移（章节重排 + frontmatter 改动 + 删表）。`drafts/disclaimer-convergence-plan-2026-10-27.md` 标 C2 在 L98、C5 在 L109、R1 在 L111，实际落点 L110 / L121 / L123；按行号改会改到隔壁句子，**而且改错了测试照样绿**（断言只认字符串）。**"编辑前"的载体也要先确认**：别用 `git show HEAD:` 复现——HEAD 是早期短稿（checklist 856 词 vs 现在 1814），收敛前的原文串在 HEAD 里 0 命中，只存在于处方文件引用的首尾 10 词里；按 HEAD 复核会误判"案例是编的"。

**预估案例**：处方 §1.2 预言 `german-a1-exam-booking-timeline` 还剩 5–6 处指令句可正面化，实际清点**全文只剩 1 处**，且改成正面对立项也不降否定数；该篇最终冻结在 26 处（15.2/千词，绝大多数是 A 类事实边界）。

## 8. 本机 `grep` 是 toybox 0.8.13，三处静默差异

**实测（同一台机器，全部有输出）**：

| 命令 | 结果 | 真相 |
| --- | --- | --- |
| `grep -c "alpha\|beta" f` | **0**，exit 1（加 `-E` → 2） | BRE 不认 `\|` 交替，静默失败 |
| `grep -nE "\bnot\b" f`（内容 `bnotb`/`not here`） | **只命中 `bnotb`**；`[[:<:]]not[[:>:]]` 才命中 `not here` | `\b` 被改写成**字面 `b`**，不是"被忽略" |
| `grep -cE "not" f`（内容 `not not not`） | **1**；`grep -oE "not" \| wc -l` → 3 | `-c` 数**行**，不数次数 |

**`\b` 那条是双向错的**：既漏计（`not here` 不命中），也假命中（`…bnotb…` 命中）。只写"恒返回 0"会让人以为只会漏；假命中的后果一样重——它同样诱导人去删掉本来正确的内容。

**三个坑都已造成实际误判**：`\b` 让三名编辑先后以为自检脚本坏了；BRE `\|` **三次复现**——一次"全仓确认某文案不存在"得出假阴性，一次我核 telc 契约时判出"`:67/:68` 两条断言不存在"（其实在，命令没加 `-E`），一次同事最小复现（`grep -c 'a\|b'` → 0 / `-cE` → 4）；`-c` 当次数会让表格式并列句少算且不报错。

**规程**：本机有 `rg` 15.2.0，`\b` 与交替都正常——**凡"已核查/零命中"一律用 rg 或 node**；必须用 shell grep 时 `-E` + `[[:<:]]word[[:>:]]`，次数用 `-oE | wc -l`，禁用 `-c`。任何"0 命中"结论都必须内建一条已知存在的阳性对照，对照未命中则脚本非零退出，贴输出时对照行一起贴。

## 11. 中文页有三把尺子，其中一把会把绿判成红

**契约**：`scheme-3-chinese-pillars.test.js:78-80`，`[\u3400-\u9fff]` 码位计数，窗口 **1800–3000**（`body` 由 `indexOf('>')` 切到 `</ZhGuideLayout>`，等于纯正文）。

**三口径实测（同五篇）**：`[\u3400-\u9fff]` 与 `\p{Script=Han}` **数值完全相等**（8 篇逐篇差值均为 0）；`\p{Script_Extensions=Han}` 多算 714（+5.8%），差量三项精确闭合：`、`(3001) / `。`(3002) / `【】`(3010-3011)，它们是 Script=Common 但 Scx=Han（另有 `〆`(3006) 只在 Scx 内），其余成员出现 0 次。后果不是"略有出入"：`german-a1-exam-booking-timeline` 契约口径 **2948（余 52，绿）**，Scx 口径 **3115（越界 115，假红）**——同一篇页、两把尺子、相反结论。**顺带把"口径"这一档拆开**：它本身还分三层——`s.length` 是 UTF-16 码元、`[...s].length` 是码点、`Buffer.byteLength` 是字节；本窗口实测有人报"`bytes=12404`"，那其实是 12,404 个码元，`Buffer.byteLength` 真值 12,466。**这三层能不能合并，只看该文件有没有星平面字符，不能按"语料"整体判断**：一条命令即可判——`[...s].filter(c=>c.codePointAt(0)>0xFFFF).length`，为 0 则码元 = 码点、前两层可合并；非 0 就必须写明用哪一层（要说"字符数"，直觉是码点）。全仓当前有 1 个反例：`drafts/Q4-TELC-EXECUTION-SPEC-2026-10-27.md` 含 13 个星平面字符（`U+1F534`×6 / `U+1F6AB`×6 / `U+1F512`×1——本文件只写码位、不写这 13 个字面字符，否则它自己立刻变成第二个反例），码元 61,864 / 码点 61,851 / 字节 88,700，**码元 − 码点 = 13，恰好等于星平面个数**——这 13 个还是作者自己用来标严重度的 emoji，等于"规范口径的人让规范本身分叉"。另外**别拿 `\p{Script=Han}` 这类属性转义代替这条判断**：那属字符集轴（哪些字算数），口径轴管"同一个字算几"，两轴正交——那 13 个 emoji 在两种字符集下都不算汉字，口径上仍一个算 1、一个算 2。同理 `wc -l` 数的是换行符个数、不是行数。
