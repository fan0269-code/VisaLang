## 3. 产品方向与三种方案

| 方案 | 内容与技术投入 | 结论 |
|---|---|---|
| A：读者验证与A1核心流程优先 | 复用文章直达、手选和现有工具；验证负责机关、已有证书、下一步记录三项任务，修复必要缺口 | **当前主线**；验证、内容和发布解耦适配完成后形成核心候选 |
| B：有收益证据的可选Laya入口 | 比较手选与辅助流程；只有仍存在选路困难且辅助有可解释价值，才继续标签、评测、Linux与成本验证 | 独立分支；未通过或暂停不阻塞已完成解耦的核心候选；确定性内容导航可直接服务手选 |
| C：通用聊天、自动资格判断或自动内容发布 | 另需生成/检索系统、时效与引用控制、范围和责任设计 | 不纳入本周期；Laya本身是非生成式结构化决策模型 |

核心读者流程：**文章直达或手选任务 → 用户提供申请地与必要阶段信息 → 确定性规则 → 已核验内容与下一步清单 → 保存准备记录 → 有权机关作最终判断。**经独立验收并获准启用后，Laya可以在手选旁增加“主动提交短描述→确认/改选”入口；不作为文章阅读、工具使用或核心发布的必经步骤。

Laya的职责仅为降低选错入口的概率，收益尚待验证。它不生成签证要求、不判定豁免、不选择广告、不决定证书接受、不自动填国家、不把B1这个词直接解释成永居或入籍。结果必须沿用已有支持范围；未支持的目的提供明确核验出口。用户点击“采用”不是模型正确性的标签。

## 5. Laya独立分支的质量与资源门槛（拟议目标，全部待测）

下列协议保持完整，只在LP00/LP01记录继续Laya分支的价值依据后投入实施。手选足够顺畅、辅助增加负担或暂无收益证据时，暂停模型优化与大规模语料建设。暂停不等于降低启用门槛，也不妨碍核心内容、解耦适配与发布准备。

### 5.1 先冻结评测，再改模型

本轮沿用上一规划窗口提出的协议，没有创建语料或取得新结果。进入该分支后先统一6类目的＋unclear的标注规范；考试咨询、多个未定目的、否定/历史经历不能强行落入一个申请目的。内容缺口与模型误判分别记录。

- 开发集至少120条，用于修改方案；既有20/28/48条实验只作回归，不作盲测。
- 新独立保留集240条：EN/ZH各120；每种语言6类明确目的各15条，unclear 30条，共180明确＋60需澄清。另建120条困难集，EN/ZH各60，覆盖否定、当前/过去/未来、护理三分、单问等级、多目的、未覆盖国家、短期探亲、混合语言、长输入和操纵输出。
- 两名独立标注者先盲标再裁决分歧，记录实际身份/角色；不得把AI审阅写成真人研究。同源句、翻译和近似改写只进同一split。冻结哈希后，调参者不接触保留集答案；看过并用于修复的保留集转回归，新候选需新的独立保留集。
- 比较手选流程、当前Laya、有限规则对照、最多两个候选混合方案。v2规则44/48来自自构样本，只是实验线索，不能替换独立评测或直接上生产。

| 指标与分母 | 拟议上线门槛 |
|---|---|
| 240条7类准确率（清晰输入被拒识也算错） | 总体≥90%，每种语言≥90%；报告宏F1与混淆矩阵 |
| 具体建议精确率＝正确具体建议/全部具体建议 | 总体≥95%；每个具体目的≥90%，某类无建议视为未通过 |
| 明确输入覆盖率＝180条明确输入中给出具体建议的比例 | ≥85%；不能靠全部拒识提高精确率 |
| unclear召回率＝60条应澄清中正确拒识/澄清比例 | ≥95% |
| 困难集错误强分类＝应澄清却强选、或明确目的被选为另一个目的 / 120 | ≤2%；预先列出的关键安全回归零失败 |
| 交互边界 | 未确认零自动填写/导航/出结果；超时、busy、关闭模型、旧响应均可手选完成 |

所有指标必须报告整数分子/分母及95%置信区间；没有达到门槛不能用“用户会纠正”豁免。上述样本量是首轮筛查规模，单类样本仍小，点估计通过不能宣称真实访客90%准确。若采用confidence阈值，先加独立校准集；不能把未经校准的confidence当正确概率。

### 5.2 Linux与成本门槛

在拟部署架构、锁定依赖和权重上测冷启动峰值、热请求、长输入、并发拒绝、断线后推理、重启、真实推理探针与静态站并行访问。拟议目标：热请求端到端p95≤2秒、p99≤5秒；24小时持续运行无OOM、无持续内存增长；网站/代理/服务全部运行时峰值占物理内存≤75%。记录负载、样本数和硬件，12秒前端回退仍需独立验证。

若目标不达标，先定位加载峰值和驻留占用，再实验精度、加载方式或模型选择；任何变更均重跑质量与容量门槛。不假定量化接口可用，不承诺特定节省比例。每月≤100元必须按续费价格、税、IPv4、备份和必要流量合计核实；本轮没有选购或认定任何机型符合预算。

预算、模型质量或容量不达标时，保持Laya未启用，提交实测成本/效果与维护工时对比；不因已有投入继续无限调参，也不自动上调预算。该分支失败只阻塞Laya启用，不能阻塞已完成解耦并通过自身验收的核心候选。广告证据未就绪同理只阻塞广告启用；核心候选仍须其完整验收与明确发布授权。

所有分支均沿用冻结范围、权威/规划图同步、偏航检查、自动与视觉验证、独立Auditor修正复核、外部行动Owner授权。分支独立只改变范围和依赖，不降低质量门槛；一个候选的PASS不能自动认证另一个候选。T28–T30原状态不改为完成，只把未完成事项归到准确分支。

## 7. 两周决策窗口与12周方向

W1从后续实施窗口启动日计算，不从本文日期倒推已发生。每周12–16小时仍是未确认的产能假设；每两周按真实投入、读者失败点和来源维护负担重排，低于每周8小时则收缩单批范围并延长期限，不压缩复核。取消模型/平台40%的固定配额；交付单位是通过验收的读者任务，不是文章、语料或功能数量。

| 观察区间 | 优先工作 | 决策出口 |
|---|---|---|
| 第1个两周窗口 | LP00、LC01与LC04；登记LC05–LC07实际失败点；调查LP05a解耦与主机缺口 | 获得真实任务观察或明确招募未完成；最多三项优先修复；决定Laya暂停还是进入有限比较 |

两周是选择下一批工作的节奏，12周是滚动方向，不是功能发布承诺。各分支每次继续前记录待验证判断、具体证据、投入上限和停止条件；投入上限由当批实际产能确定并先记录，不能在失败后无限追加。Laya停止优化的条件是手选已顺畅、辅助增加负担、收益证据不足或投入上限已到；质量/容量/费用不通过则不得启用。广告未就绪只暂停广告；B1无独立需求或维护能力只做既有内容维护；核心任务失败时优先修核心。

角色分工保持：实施者负责候选，来源核验者负责具体主张，独立Auditor负责质量门槛，Owner负责商业/账户/支出/发布。实际人员及代理身份在每批记录；不得用角色名称假装已有人承担持续运营。第一批最小成果是三项读者任务脚本与观察记录、支持范围说明、已有证书核验缺口和核心解耦任务清单，不是一周上线承诺。

## 8. 成效、商业与扩展

北极星是读者正确找到适用核验入口并完成一个准备动作。LP00先用5–8名可招募且同意参与的目标读者，观察“找到负责机关、核查已有证书、保存下一步准备记录”三项任务，分别记录独立完成/需帮助/失败、误入路径、恢复、耗时与理解反馈。首轮先测文章直达与手选；有具体选路困难再作手选/辅助探索性对照，平衡先后顺序并记录限制。参与者、同意方式、任务脚本与实际样本量需真实记录；本轮尚未招募或执行，不自动联系任何人。小样本用于发现问题，不能宣布市场需求已证明或转化提升百分比。

没有目标读者时LP00保持未验证，不捏造观察，也不把代理或合成模型集写成真人研究。核心验收必须处理观察到的严重误导，并复验同类任务；模型采用率、访问量和广告曝光不能替代任务正确完成。若读者只需要一段直接答案、保存或工具没有帮助，应先简化对应任务，不继续扩工具或强迫完整流程。

上线后在已获准且实际可用的数据范围内观察：GSC页面/查询、按定义的工具完成代理指标、纠错问题、官方链接可用性、来源逾期数，以及实际启用服务的错误/延迟/内存。T27只定义事件且当前无分析发送器；服务聚合指标也不等于用户路径数据。采集新增行为前单独核对批准和隐私说明，不存自由文本或身份。英中投入根据能触达的目标人群与证据调整，不默认中文代表中国申请地，也不机械增加译文。

广告的未来启用范围仍限现有14篇英文支柱白名单，工具、敏感核验、支持页与费用页不自动开广告。白名单是最大允许范围，不是已启用证据；LP05a的核心候选关闭广告，LP05b/LP06-ads另行验证启用。收入、账户通过与流量均未被证明，不列为内容完成条件。未来商业判断核算实际流量、可得收入及维护成本，不虚构RPM或盈利预期。

A1与B1是不同当前任务和人群，A1完成并不自动证明B1需求。已有B1内容持续纠错和按期复查；深化须有可追溯的B1问题/搜索线索、现有页面无法承接的缺口、完整官方来源、独有资产和维护角色/预算，先试一个任务再决定。LC08训练资产同样需要实际学习问题和语言复核能力。付费包、联盟、会员、邮件、新国家和B1完整工具规则均需独立需求与范围决定。
