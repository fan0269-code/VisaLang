# VisaLang：交给 Codex 的启动指令

使用方法：在 Codex 中打开 VisaLang 的真实源码项目，把本交付包解压到项目可读位置，然后粘贴下方完整指令。先阅读总规划，不需要用户再次逐项解释已确定方向。网页截图和审计报告属于证据附件，不是可直接部署的源码。

```text
你现在负责实施 VisaLang 的后续建设。请实际修改当前项目、验证并持续推进，不要只回复建议、重复总规划或询问每一个可逆实现选择。

一、先读输入
找到并阅读 VisaLang-Master-Plan.md、VisaLang-Codex-Backlog.csv、VisaLang-audit.md、VisaLang-url-remediation.csv 和 VisaLang-content-rewrites.md。总规划是本轮产品与执行基准，旧审计是现状证据，旧文案是可复核集成的起点。以任务表中的依赖开始执行 T01。各文件不在默认目录时只做有针对性的查找；不要猜测其内容。

二、固定产品方向
建设围绕德国申请场景的语言证明准备工具站。首期完成德国配偶团聚 A1：要求与适用范围、已有证书、具体考试比较、官方报名、费用、清单、时间和日历保存。随后深化 B1 永居与入籍的不同路径。先提升现有 38 篇主指南和 5 个工具，不扩成全球签证百科，不以发文数量、最低字数或更改日期定义内容质量。

三、先查真实源码
读取适用 AGENTS.md、README、依赖及锁文件、路由、内容模型、脚本和部署配置。记录当前分支、用户未提交改动、运行与构建基线，建立可恢复工作分支。历史背景为 Astro，以源码核实为准；沿用既有栈、组件和主机，不擅自迁移框架、批量升级依赖或购买服务。先将总规划里的职责映射到真实文件，再写补丁。
默认不直接编辑 dist、deploy、_headers、_redirects；遵循用户最新指令与仓库规定。找合法的源配置入口；不存在时记录精确阻塞和可审查改法，不通过副本或改规则绕过限制。不要覆盖用户修改或强制推送。

四、从可交付修复开始
优先修正已证实的核验责任错配和中文编辑指令，明确哪些路线已支持。随后完成首页和文章直接答案、字段级事实记录，再连通 Route Finder、Checklist、Comparison、Timeline、Reminder。已有工具均能生成结果，本次重点是结果真实、粒度合适、状态连续和可保存。
任务表规定建设目标；取得源码后将较大任务拆成可独立验证的小步骤，补上真实文件、实现接口和验证命令。完成一项后更新状态并推进下一个无阻塞任务，不等待日历天数，也不每一步询问是否继续。

五、内容与事实要求
关键结论绑定具体来源、适用范围、核验日期和版本。签证受理查主管机关，考试规则查具体主办方产品，当地价格与报名查所选考点。未知信息留作待核查，不能推断为免考、不符合条件或零费用。内容、工具和译文使用一致事实；阅读语言与申请地区分开。
改写必须回答标题问题并交付可使用的表格、例子、练习或清单。删除编辑残留和重复模板，保留独有内容。先完成等价承接页并核查历史价值，才执行拟合并；没有 GSC 不等于没有流量。中文本地化单独评估。不同地区范围的页面不能机械互设 hreflang，中文不能统一 canonical 到英文。

六、工具和数据约束
未支持、缺信息、需主管机关确认分别显示。清单一项一个动作，复制和打印保留逐项状态。比较表有两产品各自事实。时间首期按自然日计算并解释假设；2026-12-15、等待14天、文件准备7天、额外余量30天，应得到2026-11-24和2026-10-25。另测空值、过去日期、跨年、闰日和时区。
日历工具真实下载和验证 ICS，并在可用客户端导入；没有测试的客户端如实登记。创建日历事件不等于邮件或设备提醒已送达。默认会话内保存必要枚举；主动保存本设备时说明期限与清除方式。身份详情、自由文本、证件、完整计划、用户日期和用户输入URL不写入共享地址或分析事件。不新增账户、数据库、邮件服务、聊天机器人或实时考位库。

七、执行、验证与阻塞
任务状态用 pending / in_progress / blocked / completed；发布状态单独记录 not_deployed / preview_verified / release_ready / deployed。完成必须有相关风险的证据，不能把代码存在当成已验证。沿用测试工具，重点验证业务规则、日期、数据传递、清单状态、ICS、手机和键盘；低风险文案不增加无意义测试。
合理目录命名、组件拆分和样式调整自主完成。遇到无法访问来源、缺少统计账号、部署权限或某类日历客户端时，准确说明影响，只阻塞依赖它的部分，继续能完成的工作。不要绕过权限或自动批准审核。确实需要用户输入时集中提出最小必要问题，并说明为什么其他信息不能解决。

八、发布范围
本启动指令要求完成分支、预览和可发布版本。若当前会话已经明确授权具体环境上线，验证门槛通过后在该范围内发布，不重复索要已有授权；否则先完成全部可审查成果，再一次性提出发布所需信息或确认。不可逆删除、大批URL迁移、付费采购和范围扩展遵循明确授权与项目规则。

九、交付和续接
持续维护一个任务表、来源台账、决策记录、迁移映射、验收报告和交接摘要，优先放现有 docs 体系。每批交付具体改动、受影响URL、来源版本、验证结果、预览、已知限制与回滚方法。
结束前明确已实现、已验证、已预览、已发布、未完成和下一任务。上下文接近上限时先写交接摘要；新会话从记录续接，不重复全站审计和已完成开发。请现在从 T01 开始，先完成源码核实及能直接推进的第一批改动。
```

日后继续同一项目，可使用：

```text
继续执行 VisaLang 总规划。先读取项目中的总规划、最新任务表、来源台账和交接摘要，核对当前 git 状态。从上次未完成且依赖已满足的任务继续；不要重复已验证工作，不扩大范围。遇到已明确的选择按记录执行，只有实质阻塞才集中询问。完成本批修改、必要验证并更新交接记录。
```
