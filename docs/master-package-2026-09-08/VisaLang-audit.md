# VisaLang 全站公开页面审计与整改决策

审计日期：2026-09-08  
对象：https://visalang.org/  
交付状态：已完成公开页面审计、逐页整改清单与替换文案；尚未修改或发布线上网站。

**结论：网站具备可以继续打磨的基础，最急迫的问题是内容和工具的实际帮助不足。建议保留现有视觉体系，先做实德国 A1 配偶团聚这条路线，再深化 B1 永居与入籍。**

大量“去官方核验”的提醒，把已经能够回答的问题也变成了读者的额外作业。页面数量、字数、免责声明和核验徽章都不能代替真实答案。UI 的整改重点是把答案、操作和结果前移，降低寻找成本。

## 2. 应当保留的基础

- 首页及工具使用一致的蓝色主按钮、浅背景和清楚的标题层级，视觉不杂乱。
- A1 专题已有七步路线，能够围绕申请任务组织文章，值得沿用。
- 五个工具都能产出结果，不是纯静态占位按钮；日期倒排在本次样例下计算正确。
- 指南搜索实测有效：输入 `fees` 后，结果缩小到 3 篇相关指南。
- 有跳至正文链接、表单可访问名称、语义化表格表头和原生导航展开控件等基础。
- 配对的中英文 A1 要求文章已设置互相对应的 hreflang；实测英文切换能回到等价文章。
- 网站已主动说明范围和未上线服务，本次检查未发现冒充政府或考试机构的设计。
- [About](https://visalang.org/about/) 已说明部分研究页退出主发现范围。应在此基础上深化内容，不能无视已有整改。

## 3. 最先解决的内容问题

### C01｜P0：核验责任表把签证决定权错误地分给考试中心

[A1 费用页](https://visalang.org/guides/goethe-a1-fees-by-country/) 的核验表，将“路线要求和可接受证明”的最终决定者列为当地考试中心。考试中心能说明报名及考试规则，不能替代签证主管机关决定受理要求。同类错配也出现在 [A1 30 天学习计划](https://visalang.org/guides/goethe-a1-30-day-study-plan/) 等模板化文章。

**整改：按事实字段配置责任主体，停止为整篇文章复用一个“最终决定者”。**

| 事实字段 | 正确来源类型 | 页面写法 |
|---|---|---|
| 是否要求语言证明、是否适用例外、材料受理 | 负责申请的德国使领馆/主管机关，以及适用法律 | 说明一般规则、适用范围和个案待确认条件 |
| 考试结构、分数、模块、标准规则 | 准确考试产品的主办方 | 链接具体产品/规则页，直接摘出对决策有用的事实 |
| 当地价格、报考日期、证件、退改、出证 | 所选官方或授权考点 | 标清地点、类别、适用时间和核验日 |
| 复习节奏、练习建议 | VisaLang 的编辑性建议 | 标为建议，不能包装成官方承诺 |

验收：所有模板及指南检查此字段；不存在“考试中心决定签证是否受理”的表述。练习页的证据表改为考试结构与练习材料，不强行套入签证审批字段。

### C02｜P0：中文正文暴露内部编辑检查要求

[中文 A1 主指南](https://visalang.org/zh/guides/german-family-reunion-language-requirement/) 在申请人行动步骤中夹入“检查文中”“检查 hub 链接”一类编辑工作。这些内容不能帮助申请人判断下一步。

整改：从前台移除，迁到内部发布检查。替换为申请人真正需要做的动作：确定申请类别、核对配偶居留依据、查看负责使领馆的当前清单、记录已有证书、解决未确定事项。配套文案包已给出替换正文。

### C03｜P1：标题要求具体答案，正文只描述核验方法

费用、证书比较、资格要求和部分 FAQ 都存在这一问题。“直接答案”区常常是文章摘要或提醒，没有回答标题本身。**费用因地区不同而变化，不意味着不能写任何费用。**

例如官方当前公布的成人 A1 价格包括北京在读学员 1,400 元、非在读学员 1,500 元，以及德国价目中的 155 欧元。可以发布带地点、类别、年份与核验日的小型价格表，不应假装有全球实时数据库。[北京官方价目](https://www.goethe.de/ins/cn/zh/spr/prf/anm.html)、[德国官方价目](https://www.goethe.de/ins/de/zh/prf/pre.html)

整改：每篇第一屏交付一项真实答案；随后再解释适用边界、来源与变化条件。不要用“无法保证你的个案”回避描述已核实的一般规则。

### C04｜P1：同一模板反复覆盖不同任务

本次对全部 30 篇英文主指南的正文提取做了重复项检查：

| 重复模式 | 本次数量 | 判断 |
|---|---:|---|
| 同一组三条 Key decisions | 30/30 | 学习、费用、考试规则和签证要求被套进同一流程 |
| 两块 Verify before you act | 30/30 | 反复占用正文前部空间；不是每块提醒都应该删除 |
| 同一组三条 Common mistakes | 15/30 | 错误示例与文章任务不够贴合 |
| 正文近似英文词数，含模板 | 778–1494 | 问题不是简单字数不足，也没有计算出所谓“原创率” |

整改：保留一处必要边界提示；由页面任务生成独有正文与证据表。删除空泛重复不能连带删掉地区规则、独有例子、真正的失败处理或官方证据。

### C05｜P1：证书有效与签证受理新近性没有解释清楚

Goethe 证书本身不设到期日；接受材料的机构可以另设取得时间要求。德国驻华使领馆当前说明通常接受考试日期在一年内的证书。两者是不同层次，不能写成“Goethe 证书一年失效”，也不能以“永久有效”推导任何旧证书一定被受理。[Goethe FAQ](https://www.goethe.de/ins/us/en/spr/prf/ogf.html)、[驻华使领馆说明](https://china.diplo.de/cn-zh/service/visa-einreise/2716606-2716606)

整改：在证书页面增加两层规则表与已有证书分支，标明中国申请范围。英语全球页面不要把驻华规则推广为全球统一要求。

### C06｜P1：B1 文章仍需把不同法定路径讲清

当前 B1 内容能区分语言与其他材料，这个方向正确。但“各路线不同”之后，需要进一步给出路径对照和依据。例如普通永居、技术人才永居及欧盟蓝卡路线不能混用一套月份与语言阈值；入籍也有独立依据。先补条件表，再给学习和报考建议。[居留法 §9](https://www.gesetze-im-internet.de/aufenthg_2004/__9.html)、[居留法 §18c](https://www.gesetze-im-internet.de/aufenthg_2004/__18c.html)、[国籍法 §10](https://www.gesetze-im-internet.de/stag/__10.html)

**特别核正：浏览器确认 B1 hub 有永居和入籍两张可点击路线卡；A1 hub 也有官方入口。它们不是空章节。** 文本抽取漏掉卡片，不能当作页面缺失。

### C07｜P1：学习文章需要可用的训练材料

保留学习任务，但不能每篇都只写“每天练习、记录错误、用官方样题”。听力页需要可访问材料入口和听后分析；写作页需要原创题目、示范和修改解释；口语页需要角色任务与反馈表。30 天与 8 周计划应有不同起点和调整方法，不应暗示零基础按天数必过。

### C08｜P2：内部状态词削弱读者理解

首页、文章卡片、About 有内容结构状态和编辑流程术语。普通读者需要知道核查范围、最新事实和该做什么，不需要知道站点如何设置元数据闸门或准备 AdSense。

整改：将内部状态留在后台；前台用“适用地区”“核验日期”“本页覆盖内容”“尚待确认事项”。真实作者或编辑负责人可以补充，不能虚构律师、考官、审核专家或虚假资历。

| U14 / P1 | 中文文章大量主导航和工具入口标为英文（12） | 中文内容链到核心工具时体验中断 | 首先完成 A1 路线、清单、时间工具中文界面；不要求一次翻译全站 |
| U15 / P2 | Exams 真实渲染有 31 张卡，跨 11 个分组，含护理、医学和贷款执照（08） | 产品范围被拉宽，卡片主要是机构入口 | 默认围绕德国当前支持考试；其他内容收为低优先级参考，不制造专业路线支持印象 |
| U16 / P2 | Exams 日期徽章换行拥挤；部分并排按钮之间很紧（08、13） | 次要信息抢视觉，触控目标不易区分 | 日期不做宽重徽章；操作区采用明确间距与自动换行 |
| U17 / P2 | 未来付费服务频繁出现在相关动作中，Pricing 列多个尚未提供服务 | 读者来到未能交付的服务出口 | 把主要动作改成实际免费工具与指南；未来产品集中一个简短状态区域 |

以上像素范围、间距和内容优先级是设计建议，不是未经测量的当前 CSS 值。没有测得对比度不达标，也没有完整键盘和读屏测试，不能据此下“无障碍失败”的结论。

建议保留现有品牌蓝与浅色背景，减少嵌套色块、重复徽章和大面积提示框。申请工具的重点是清楚、稳定、容易核对；无需为了高级感加入更重的玻璃、模糊或动画。

## 6. URL 处置决策

**目前不要批量删除38篇指南，也不要全部 noindex。** 每页分配一个独立用户任务，先补齐有价值内容，再进行必要合并。配套清单逐页给出优先级、任务、拟处置、独有交付物、承接页、核实状态与验收。

| 页面组 | 建议 |
|---|---|
| A1主要求、证书、比较、费用、考点、时间、材料 | 保留现有主要URL，重写并加强各自任务 |
| A1 booking mistakes 与 pre-booking checklist | 优先以报名前清单承接独有错例；上线前看GSC/外链，再落实301 |
| A1 FAQ | 有价值的问答回归具体主页面；没有独立任务时再合并，不能整篇粗暴跳到一个不覆盖全部问题的页面 |
| A1 30天与8周计划 | 有不同起点、节奏、实例时分别保留；若只是改天数，改为一个可切换计划 |
| A1/B1 听说写技能文章 | 优先补原创练习资产；不能仅因标题相近就删除 |
| B1 difficulty / study / mock | 分工为诊断、计划、演练；无法实现独立产出时，先把重复部分整合到学习中心 |
| 中文8篇 | 保留本地化价值；中文报名前指南目前有独立角色，不能直接沿用英文合并规则 |
| A1/B1 分类集合 | 路线hub承担流程，分类页承担浏览时可以共存；相同列表无额外用途时再按数据合并 |
| 暂缓研究页 | 维持不进入主要导航/广告；逐页核实noindex与sitemap规则。没有完整来源和独有任务，不恢复发现 |
| Pricing与未来服务 | 降低入口权重，收拢为清楚的服务状态；无内容占位页不投放广告，不必为不存在服务建多层页面 |
| About/Contact/Privacy/Terms/Editorial | 保留真实信任与使用目的，精炼正文；不以点击低为由删除 |

301必须先有完整承接页，旧内容中的有用资料必须迁入，站内链接和sitemap同步更新。暂缓、合并与删除是不同动作；`noindex`不是整改质量的替代物，也不要用 robots.txt 阻止抓取后指望 Google 看见 noindex。[Google noindex说明](https://developers.google.com/search/docs/crawling-indexing/block-indexing)、[Google站点迁移说明](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes)

## 7. SEO、可信度与广告结论

本次不支持“已经被Google处罚”“一定无法通过AdSense”或“没有自然流量”等判断。没有后台数据，不能把风险描述为已发生的结果。

Google强调内容能否帮助读者完成目标，没有偏好的文章字数，也不认可仅为制造新鲜感而批量增删内容。VisaLang应先做出独有的比较、清单、记录与解释，不能把给长文加日期、加免责声明、加官方首页链接视为内容升级。[Google以人为本内容指引](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)

广告方面，低价值、无发布者内容和建设中页面存在明确政策限制。应先保证页面自身有可用内容，再谈广告；不能承诺“达到某篇数或字数就能通过”。本次没有核实每页广告是否实际加载。[Google发布商内容政策](https://support.google.com/publisherpolicies/answer/11112688?hl=en)

| 技术检查 | 本次观察 | 后续动作 |
|---|---|---|
| 首页 canonical | 自指 https://visalang.org/ | 保留，核实全站域名/尾斜杠一致性 |
| 首页多语言 | en、zh-CN、x-default指向相应首页 | 保留；不应把全部文章中文版本指向中文首页 |
| A1要求双语 | 各自self-canonical，hreflang双向对应 | 以此模式核实其余等价版本 |
| 费用页 | index,follow；self-canonical；无hreflang | 当前没有对应中文费用页，无hreflang本身不是错误 |
| 文章结构化数据 | 英文A1要求页存在Organization、Article、BreadcrumbList | 后续校验字段和可见内容一致，不要凭存在就称Rich Results全通过 |
| H1 | 64页公开提取均识别1个H1 | 是正向信号；仍需源码检查真实语义和页面标题质量 |
| 真实速度 | 无Lighthouse/CrUX证据 | 测量后再决定图像、字体和脚本优化，不能编造性能分数 |
| 手机表现 | 未完成真实窄视口测试 | 375/390/768px、键盘、表格、菜单、打印列为发布门槛 |

## 8. 整改后的网站应交付什么

核心访问路径：读者知道自己属于哪类申请，看到有依据的一般要求和例外入口，比较准确考试产品，记录当地报名条件，生成一份可以带走的计划。所有未知项明确保留，避免伪造个人结果。

建议未来首页按下列顺序组织：

1. 德国 A1 的明确价值、主要按钮和覆盖范围。
2. “我是否需要A1 / 已有证书 / 准备报名”三个任务入口。
3. 一张真实工具结果样例，帮助读者理解能带走什么。
4. 四个常用工具与必要指南，不反复堆同一个 Route Finder 链接。
5. 来源核查方法、最近发生了什么实质修订。
6. B1 永居/入籍作为下一条专题；未来产品降低优先级。

不要把尚未做好的结果样例包装成已上线功能；首页文案必须与本次实际可用范围一致。

## 9. 实施顺序与投入判断

完整日程、12项内容brief、数据字段、任务验收、回滚方法和Codex提示词见 `VisaLang-implementation-plan.md`。建议估算为120–180人工小时，前提是沿用现有代码、只深化有限地区、不开发实时考位库。实际排期应在取得源码后重新估算。

| 时间 | 可交付结果 | 发布前门槛 |
|---|---|---|
| 第1–3天 | 核对源码/页面台账、修正文案错误与编辑指令、暂停重复批量发文 | P0事实错配清零；修改可回滚 |
| 第4–7天 | 缩短首页与文章首屏、修正支持范围、完成首批替换稿集成 | 新旧事实一致、链接可用、无误删 |
| 第8–14天 | A1要求、证书、比较、报名清单四项资产 | 每项能解决独立问题，并有就近官方证据 |
| 第15–30天 | 费用/考点/时间/考日材料，连通工具并进行条件式合并 | 清单状态可带走；日期可复算；迁移单跳 |
| 第31–45天 | B1永居/入籍与考试差异，核心中文工具 | 完整核验的分支才标为支持 |
| 第46–60天 | 原创训练资产、用户任务测试、索引及性能复核 | 维护责任与更新队列明确；按结果决定扩展 |

如果每周只能投入10小时，将目标缩为A1核心链路，完整计划通常需要12–18周。不要因为用AI而把证据核验、人工编辑、翻译和发布检查的时间记为零。

首月先看工具是否能用、任务是否完成、错误是否减少；自然搜索与广告收益的变化需要后台数据和更长观察，不能作为保证结果。
