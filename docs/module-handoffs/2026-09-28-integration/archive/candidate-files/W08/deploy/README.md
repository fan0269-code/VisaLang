# VisaLang website and purpose-provider deployment

This runbook replaces the former clone/pull deployment and static-only rollback workflow. `deploy.sh` now requires a prepared immutable bundle and a bound approval receipt; it never pulls `main` or builds on production. Do not run `server-init.sh` on an existing host: its firewall reset is first-host scaffolding, not a migration command.

1. The sole runtime feature contract is `dist/runtime-features.json`, emitted from `src/data/runtime-features.ts`. Set `VISALANG_PURPOSE_MODE=off|laya|typesafe` and `VISALANG_ADS_MODE=off|on` before building; both default to `off`. Use the same environment for `npm run launch-check`. Release flags do not select modes. Ads mode only gates existing publication-manifest eligibility; it does not add eligible pages.
2. After separately authorized commit, run `npm ci`, `npm test`, `npm run launch-check` and Python service tests on the exact candidate. A dirty checkout may be packaged for inspection, but activation rejects it. The launch check is **local candidate verification**, not account/server readiness.
3. Build a purpose-service image only for `purposeSuggestions=laya|typesafe`, on Linux amd64 with `docker build --platform linux/amd64 --build-arg PYTHON_IMAGE=python:3.13-slim@sha256:<verified-base-digest> services/laya-purpose`. Use the reviewed Python 3.13 base digest obtained from the registry; no example digest is a usable value. `requirements.lock` is resolved for Linux x86_64/Python3.13 with CPU PyTorch and hash-checked wheels. Record the resulting image digest and SBOM/package inventory. No Docker build is claimed by a dependency resolution receipt.
4. Stage exact checkpoint bytes from `services/laya-purpose/model.lock.json` only for Laya mode. Keep the locked `multilingual/` subtree readable to UID10001. TypeSafe mode does not need a Laya revision or weight cache; it requires the `TYPESAFE_API_KEY` host secret. Purpose-off needs no Python image, model, TypeSafe key, service container or Nginx proxy.
5. `python3 deploy/release.py prepare /tmp/<release-id> [--image <registry/repository@sha256:digest>] [--model-revision <locked-revision>]` derives mode from the built contract and produces `site/`, mode-specific `nginx/`, source input hashes and `release.json`. Supply `--image` for either enabled provider and `--model-revision` only for Laya. Use a lowercase alphanumeric/hyphen ID. Do not rename the bundle; Nginx paths bind its installed name. Inspect with `python3 deploy/release.py verify /tmp/<release-id>` and transfer it without changing bytes to `/var/www/visalang.org/releases/<release-id>/` in an authorized window. Keep it root-owned and non-writable by the web/container users. Transfer/host setup is not performed by prepare.
6. Fill a private copy of `production-evidence.example.json` with actual Owner authorization, exact release-manifest SHA256 and previous manifest SHA256 (null only on first install). Required evidence documents must exist beside/below the receipt, have a mode-appropriate status and matching SHA256. Ads-off requires `adsConsent=not_applicable` backed by real zero-load/zero-page evidence; purpose-off requires `capacity=not_applicable` backed by proof of no optional service dependency. TypeSafe also requires separate privacy/processing and price/quota evidence. Never mark missing evidence pass to enable the command.
6. In the separately authorised production window, run `sudo bash deploy/deploy.sh <verified-bundle-path> --approval <private-receipt-path>`. Nginx's enabled site must be absent or a managed symlink; migrate any existing unmanaged vhost after inventory. The host needs Docker, Nginx, curl, Python3 and TLS certificates for apex/www before this step. Do not install another duplicate `visalang_purpose` rate zone or old vhost. A trusted CDN needs separately verified real-IP configuration.
7. The release manifest stores the canonical `features` object. Legacy v1 manifests without `features` remain compatible only when `adsRequired` is an explicit boolean and the provider is legacy Laya or a structurally valid TypeSafe release; absent provider means legacy Laya. Contradictory fields, unknown values, and missing ad state are rejected. Before staging Nginx or replacing a container, activation checks that both target and current release can start: TypeSafe key for TypeSafe releases, verified model cache for Laya releases, and both image digests when a provider is enabled. Purpose-off releases need none of these and omit the purpose proxy. Mode changes restore the previous provider/config/pointer on failure. `/api/purpose-suggestion/` GET probes test only the HTTP method guard (405 enabled, 404 off); they send no text and make no model API call. Static HTTP/TLS smoke does not establish model quality, account readiness or consent behavior. The short service replacement interval can return manual-fallback responses; this is not a zero-downtime promise. If restoration fails, the command fails and requires operator intervention. First-install rollback and uncatchable host failure still require the recorded old-DNS/old-host plan and explicit operator action.

Never put a TypeSafe key in a manifest, command-line value, source file, build arg, image, browser bundle or log. TypeSafe requests send user-entered descriptions only in TypeSafe mode after a user click. The UI and policy disclose U.S. processing, potential retention, the provider's no-training statement, and unresolved local price/quota/account settings. A production activation still requires separate Owner authorization and all release evidence.
8. Explicit rollback: `sudo bash deploy/rollback.sh <verified-bundle-path> --approval <rollback-receipt-path>`; the receipt must authorize rollback and bind the current previous release. Both commands verify hashes again. Keep every previous bundle, image and model until the observation window closes; no automatic cleanup runs.

### Required production evidence

- Independent audit of exact source/artifacts, separate from authorization.
- When ads are on: Ads/CMP account configuration, applicable consent behavior, Auto ads page exclusions for tools/closed pages, exact ads.txt seller and real browser network behavior on eligible EN content and ad-free tools. When ads are off: preserve a verified zero-loader/zero-page evidence record as `not_applicable`, never as consent pass. Raw HAR files and screenshots must not be committed to Git; sanitize any account/browser evidence. A script URL in HTML is not evidence of actual consent or delivery.
- For TypeSafe mode: current provider terms and processing evidence, account-specific pricing/quota/budget evidence, and independently measured performance/quality before any claim about fit. Official API docs describe token usage, not VisaLang's price or account quota. For Laya, retain the existing local-model lock and target-host capacity gate.
- Target 2vCPU/4GB Linux host: cold load, repeated requests, busy/429 behavior, static requests during inference, container restart, peak RSS and cgroup/OOM state. Container memory starts at 3GB to leave OS/Nginx headroom. This is an unvalidated allocation until measured. Successful inference must fit the client's 12s timeout; do not use macOS results as target-host capacity evidence.
- Pre-DNS TLS/SNI, all 17 retained paths, canonical/noindex rules, API through Nginx and rehearsed rollback. Public probes currently cannot establish live old-route behavior (403/timeouts).
- Exact prior DNS records and prior live host/version recovery procedure. The user controls DNS but has not authorized a change in this implementation window.

The service's `/internal/metrics` returns fixed aggregate counts, total inference seconds, busy state and process peak RSS. It is not proxied publicly; collect locally only. It excludes raw input, URL query, IP and text-derived labels. `/healthz` only means the local model loaded, and the transaction's GET method probe only proves the HTTP guard is reachable; neither proves purpose quality. Any future live inference probe requires its own explicit request, data and cost authorization. Budget <= CNY100/month excludes the domain but includes applicable tax, IPv4 and backup costs; no server has been purchased or selected as available. T31 public checks and 24h/day7 observations begin only after an actual launch.
